# 颌一口腔 AI 工作台

> 2026「1024 超能 Coding 周末」· 颌一口腔真实命题
> 方向 A（AI 多渠道内容生产工具）+ 方向 B（AI 售前咨询与客户服务助手）协同实现

一套可运行的 Web 应用，把门诊已有的专业资料变成两件能天天用的东西：
**运营能持续产出可信内容**，**客户咨询能被及时、准确、有温度地接住**。

## 一、快速开始

从 GitHub 克隆后无需安装任何依赖（零 `npm install`）：

```bash
git clone <仓库地址>
cd heyikouqiang-ai-workbench
node server.js          # 或 npm start
```

打开 http://localhost:5173 会先进入**登录页**。

| 账号 | 密码 | 身份 | 可见范围 |
| --- | --- | --- | --- |
| `admin` | `heyi2026` | 门诊负责人 | 全部功能 |
| `ops` | `heyi2026` | 运营人员 | 门诊信息、内容生产、到店导览、模型配置 |
| `front` | `heyi2026` | 前台接待 | 门诊信息、客户工作台、到店导览 |

> **部署到公网前务必设置环境变量 `CLINIC_PASSWORD`**，它会覆盖上表的演示默认密码。
> 演示账号仅用于本地体验，正式使用请接入门诊既有账号体系。

登录后可停留 7 天；顶部导航右侧显示当前身份，点「退出」即失效。
**客户咨询入口 `/consult` 无需登录**，扫码直接进入——这条链路不能被登录墙挡住。

### 大模型（可选）

不配模型也能完整运行：全部功能走本地知识库与模板引擎。要启用大模型润色，二选一：

```bash

cp config.example.json config.json    # 或写入文件（该文件已被 .gitignore 忽略）
```

也可以在启动后的「模型与知识库」页面填写，密钥保存在 `store/llm.json`（同样不入库）。

| 入口 | 地址 | 给谁用 |
| --- | --- | --- |
| 登录页 | `/login` | 门诊标识 + 品牌名，岗位账号登录 |
| 门诊信息首页 | `/` | 门诊简介、服务、医生团队、环境相册、**每日口腔科普与科普库**、工具入口 |
| 到店导览 | `/map` | 客户（地铁 / 自驾路线、实景示意、一键地图导航） |

## 二、数据从哪来

全部来自门诊提供的《颌一口腔门诊资料包》，由 `tools/extract.js` 一次性抽取：

| 产物 | 内容 |
| --- | --- |
| `data/qa.json` | 91 条门诊标准问答（原编号 QA-001 ~ QA-091） |
| `data/clinic.json` | 门诊名称、地址、电话、门诊时间、预约规则、服务项目、导航说明、2 位医生 |
| `data/facts.json` | 10 条门诊基础信息条目（由资料包第二节整理） |
| `assets/*.jpg` | 12 张门诊实拍图（2 张医生介绍卡、8 张环境图、2 张导航示意图） |

**为什么额外做 `facts.json`**：原题库只覆盖问答，但客户会问「你们环境怎么样」「几点下班」「坐地铁怎么去」——这些信息资料包里有，却不在题库里。不做这层，AI 会对着已有的资料说"我不知道"，然后转人工。这 10 条填补的就是这个洞。

## 三、方向 B：AI 售前咨询与客户服务助手

### 工作方式

一句话进来，先做**风险分级**，再决定是自己答还是转人工：

```
急症 > 用药 > 诊断/费用 > 排班号源 > 医生资质 > 正常问答
```

| 等级 | 触发示例 | 处理 |
| --- | --- | --- |
| 急症 | 「拔牙后大量出血止不住」 | 立即引导就医 + 标记**加急**转人工 |
| 用药 | 「拔牙后能吃甲硝唑吗」 | 转医生，提示不要自行停药 |
| 诊断/费用 | 「嘴巴张不开还有白斑，要花多少钱」 | **不诊断、不报价**，说明需检查后评估 |
| 排班 | 「明天下午三点有号吗」 | 转工作人员实时确认，不承诺号源 |
| 医生资质 | 「你们医生是博士吗」 | 转门诊核对后的书面介绍 |

### 检索怎么做到"答得准又不瞎答"

三层处理，缺一不可：

1. **口语改写**：客户说「几点下班」「坐地铁怎么去」「环境设施怎么样」，改写成资料里的书面说法再检索；
2. **同义词扩展**：洗牙=洁牙=洁治，涂氟=防龋，矫正=正畸=戴牙套……只用于打分；
3. **IDF 加权覆盖率闸门**：只用知识库里真实出现过的词算覆盖率，低于阈值就判"未命中"——宁可转人工，也不让 AI 对着「你们有夜诊吗」答出一段医生介绍。

未命中时 AI 说的是：「这个问题在我的资料里没有查到可靠依据，我不想给您一个不确定的答复。」然后转人工。

### 预约流程（多轮槽位 + 工作日分流）

槽位：就诊人称呼 / 联系电话 / 意向项目 / 时间偏好。收集齐后出确认卡片，确认即提交。

客户提出周末时，AI 会**先说明客观情况再给选择**：

> 门诊周末接诊时间是 08:45–17:45，工作日是 09:00–18:00，周末号源相对紧张一些。如果时间能调整，工作日的时段通常会更宽裕；当然，如果您只有周末方便，我们完全尊重您的安排，会按您希望的时间去协调。

客户若仍坚持周末（说出「还是」「坚持」等），AI 会明确尊重、不再重复建议。**不替客户做决定，也不硬推。**

### 其他

- **适老化模式**：一键放大字号，回复自动精简为短句、去掉括号补充说明
- **授权后才留存**：收集联系方式前弹窗说明用途，客户可拒绝；拒绝后工作台显示"未授权"，提示不要主动外呼
- **复合意图**：一句话里又有提问又有预约（B1 场景），先回答问题，再引导登记

## 四、方向 A：AI 多渠道内容生产工具

### 五个平台的差异是真的差异

| 平台 | 形式 | 差异点 |
| --- | --- | --- |
| 小红书 | 图文笔记 | 搜索型标题 + 三段式要点 + 话题标签 |
| 抖音 | 短视频脚本 | 0–3s 钩子前置 + 分镜表（时间/画面/口播/字幕）+ 结尾行动指令 |
| 视频号 | 视频脚本 + 转发语 | 语速舒缓、字幕偏大，照顾中老年与家长 |
| 公众号 | 长图文 | 分节标题 + 要点 + 温馨提示 + 门诊信息卡片，1200+ 字 |
| 朋友圈 | 短文案 | 3–5 行，配图建议 |

同一主题在四个平台的**标题与正文完全不同**（冒烟测试有断言校验），不是同一段话改字数。

### 三种创作来源

- **主题创作**：输入「儿童涂氟」等主题，常用主题一键填入
- **节气科普**：内置 24 节气 × 气候特点 × 口腔关注点 × 长沙本地生活，例如霜降会关联"冷热交替、火锅热饮增多→牙齿敏感与牙龈出血高发"
- **门诊素材**：选医生介绍卡或环境照片，转成介绍文案

### 素材使用有硬约束

上传门诊真实素材时，界面会明确标出约束：

- 医生：**只用已核对的姓名与"医师"身份**，不添加职称、毕业院校、执业年限、疗效表述
- 环境：只描述图片中真实可见的内容，**不虚构设备型号，不暗示设施全天开放，不涉及医生排班承诺**

### 合规体检

每条生成内容自动过一遍，命中即标记 + 给出改写建议：

| 类别 | 拦截内容 |
| --- | --- |
| 疗效承诺 | 保证、根治、彻底、100%、一定、绝对、永不 |
| 无痛宣传 | 无痛、一点也不疼、毫无痛苦 |
| 绝对化用语 | 最好、顶级、国际领先、最先进、权威、特效 |
| 虚构资质 | 博士、主任、教授、毕业于、从业 X 年 |
| 价格信息 | 任何具体金额 |
| 制造焦虑 | 癌变、后悔一辈子、再不…就晚 |

已针对「第一个问题」这类序数用法做了排除，避免误杀正常表达。保存时会对**编辑后的文本重新体检**，不合规的标记为「待修改」。

### 可交付

标题与正文都是可编辑输入框，支持：复制全文、导出 Markdown（含内容依据与配图建议）、存到内容库、标记已审核、换个角度重新生成（4 种切入角度）。

## 五、每日口腔科普与科普库

首页 `/` 的「每日口腔科普」区块，把门诊标准问答变成一个每天自动更新的栏目。

**内容筛选**：101 条标准问答里，剔除纯报价条目（结论一律是"需面诊报价"，没有科普价值）和门诊运营类（位置、预约、医生简历），剩 **72 条**口腔健康知识，按读者视角重新分成 7 组：

| 分组 | 条数 | 覆盖的问题 |
| --- | --- | --- |
| 🧸 儿童口腔 | 27 | 涂氟、窝沟封闭、乳牙龋坏、早期矫治、孩子看牙配合 |
| 🌿 洗牙与牙周 | 6 | 洁治常见误解、洗牙频率、牙周维护 |
| 🛠️ 补牙 | 4 | 补牙后的使用、护理与复查 |
| 🦷 拔牙 | 11 | 麻醉、术后饮食护理、什么情况要联系门诊 |
| 😁 牙齿矫正 | 4 | 矫正时机、周期、检查流程 |
| 🔩 种植牙 | 12 | 术前评估、使用年限影响因素、术后维护 |
| 🚭 槟榔与口腔黏膜 | 8 | 湖南地区高发的咀嚼槟榔相关问题 |

儿童相关占比最高（37.5%），这是门诊资料本身的构成，门诊也确实主打儿童友好就诊。

**每天推哪一条**：由 `lib/daily.js` 决定，不依赖任何存储状态。

- 预先生成一张长度 72 的排期表，用加权轮转（权重 = 该组条目数）算出每天轮到哪个组，组内依次发牌
- 取 `绝对天数 mod 72` 索引，所以跨年连续、不依赖年份
- 每 72 天，72 条各出现一次，不重不漏；同一条最短 72 天后才会重现
- 相邻两天不会撞同一组（权重最大的儿童口腔也低于半数，且排期首尾不同组，跨周期边界不撞车）
- 同一天所有访客看到同一条，隔天自动更换

**首页上有什么**：

- 今日卡片：日期、所属分组、风险提示徽标、问题与答案全文、来源编号（如 QA-074）
- 风险提示三级：`通用口腔常识` / `需医生检查评估` / `不适请及时联系门诊`，依据答案是否涉及个体差异、是否需先看诊、是否为术后异常提示自动判定
- 未读红点：当天第一次打开时出现，之后自动消失
- 往期回顾：最近 6 天，点击可回看；「明日预告」给出明天的标题
- 科普库：7 个分组筛选 + 关键词搜索，点击展开答案，可一键「去问助手」
- 「复制这段科普」：带门诊落款，直接粘贴到朋友圈或客户群

**演示任意一天**（现场不用等到明天）：在首页地址后加 `?d=日期`

```
http://localhost:5173/?d=2026-10-26
```

**与咨询的闭环**：点「带着这个问题去问助手」跳到 `/consult?q=问题`，助手预填输入框并弹出衔接语，客户改改就能发送；由此产生的线索，在工作台里来源会记为「每日科普」。

## 七、双引擎：本地优先 + 大模型可选

**默认完全离线可用。** 所有业务逻辑跑在本地引擎上，断网、评委机、无 Key 都能完整演示。

想让文案和对话更自然，在 `/settings` 配置任意 OpenAI 兼容接口（DeepSeek、混元、通义、OpenAI、本地 Ollama 均可）：

| | 本地引擎 | 大模型增强 |
| --- | --- | --- |
| 依赖 | 无 | baseURL + apiKey + model |
| 断网 | ✅ 正常 | 自动降级本地 |
| 输出 | 模板化，稳定可预期 | 更自然，随机性更高 |

**安全设计**：大模型的输出不会直接放行——

- 咨询回复：把检索到的知识条目塞进 system prompt 约束其"只润色不补充事实"，输出还要再过一遍合规体检，不通过就回退本地引擎
- 内容生成：同样体检，不通过就保留本地版本并在界面上说明原因

换句话说，**大模型只能让表达更好，不能让它说得更多**。

## 九、现场演示建议（约 5 分钟）

**闭环演示**：科普 → 咨询 → 工作台（约 3 分钟）

0. `/` 下滑到「每日口腔科普」→ 今日卡片（日期 + 分组 + 风险提示徽标 + 来源编号）→ 地址栏加 `?d=2026-10-26` 回车，演示「明天会自动换成这一条」→ 右侧「往期回顾」可回看最近 6 天 → 下方科普库搜「洗牙」看分组筛选与展开
1. 点今日卡上的「带着这个问题去问助手」→ `/consult` 输入框已预填，直接发送 → AI 依据同一条知识作答
2. 接着说「周六上午，我叫李婷，13800001111」→ 触发工作日分流 → 确认
3. `/workbench` 看到这条线索，来源标记为「每日科普」

**完整演示**：内容生产 → 咨询 → 工作台

1. `/content` 输入「儿童涂氟」，勾选小红书 + 抖音 + 公众号 → 生成 → 展开「内容依据」展示可追溯 → 存到内容库
2. `/consult` 输入 *「我家孩子6岁，想带他去涂氟。你们那里环境怎么样？需要提前预约吗？」*
   → AI 先答环境与预约规则，再引导登记 → 「周六上午」触发工作日分流 → 留姓名电话 → 确认
3. 新开会话输入 *「我的嘴最近张不开，口腔里面还有白色的东西，是不是很严重？要花多少钱治疗？」*
   → 不诊断、不报价，转人工并弹授权
4. `/workbench` 展示两条线索：一条预约意向、一条加急转接，含摘要、对话记录、授权状态 → 改状态、加备注

**边界演示**（可选）：
- 故意改文案为「保证无痛，100% 根治，只要 1999 元」→ 合规体检立刻标红
- 问「你们有夜诊吗」→ AI 承认不知道并转人工，而不是编一个答案
- 断网后重新演示 → 本地引擎照常跑通

## 十、边界与声明

- AI **不做诊断、不给治疗方案、不给具体报价、不承诺排班号源**，相关内容一律转人工/医生
- **不虚构**医生履历、成功案例、疗效数据、停车收费标准；资料中没有的信息明确说明并转人工
- **不制造焦虑**促成交易，不使用夸大疗效的表述
- 客户联系方式在**告知用途并取得授权后**才留存，可随时要求删除
- 演示数据均为模拟；涉及医疗判断的内容由专业医生负责审核
